GetJobsPro 面向“只投真正合适的岗位”的求职场景：每一条发给 HR 的消息都要先通过规则与 AI 的双重判定，不确定就不发送；浏览与投递按接近真人的节奏进行，遇到平台风控立即停下，长期稳定运行在无界面的 Linux 服务器上。

## 核心特性

### 发送前必过的岗位匹配闸门

- Boss 直聘与智联招聘共用同一套匹配规则（`match_rule` 表），在管理页「岗位匹配规则」卡片中编辑。
- 判定顺序：信息完整性 → 岗位名称必含词 → 岗位名称排除词 → AI 复核 → 招呼语校验，任一环节不通过或出错都不发送。
- AI 复核只接受结构化结果 `{match, score, reason, greeting}`，`match` 为真且分数不低于阈值才放行；AI 超时、报错、返回无法解析时一律不发送，不会退化为只按名称规则发送。
- 招呼语有长度、格式与禁用词校验，AI 生成内容不合规时回退为固定招呼语，固定招呼语也不合规时不发送。
- 启动投递前自动自检（必含词、技能介绍、招呼语、AI 连通性），不通过时任务不启动并给出原因。
- 每个岗位的判定结果写入投递记录，管理页可查看判定明细；「粘贴岗位试判定」可在不发送任何消息的情况下核对规则口径。

### 卡片标题预过滤

- 搜索列表中先按岗位卡片标题执行名称规则，不符合的岗位不点开、不调用 AI，节省请求量也减少页面操作。
- 近期已处理过的岗位（已投递、规则未变化时已被过滤）直接跳过；修改匹配规则后，之前被过滤的岗位会按新规则重新判定一次。

### 接近真人的浏览节奏与风控保护

- 每个关键词不设搜索上限，列表按批次滚动加载，每批之间随机停顿。
- 点开岗位后随机停留，每点开一定数量的岗位做一次批次休息，切换关键词前再休息一段时间；随机停顿偏向较短一端，避免均匀分布的机械特征。
- 检测到平台安全验证页时立即停止任务，提示人工完成验证后再启动。
- 连续多个岗位取不到详情时自动停止，避免在异常页面上反复操作。
- 每日打招呼次数上限：按真实发送次数统计，达到上限当天自动停止，次日恢复。

### 多张图片简历

- Boss 直聘打招呼后按顺序发送最多 5 张图片简历，每张确认发送成功、状态稳定后再发下一张。
- 管理页一次多选上传，按文件名自然顺序排序。

### 智联招聘接入同一闸门

- 智联投递前读取岗位描述并经过同一套匹配规则，判定通过才投递。
- 「从 Boss 同步」一键复用 Boss 的关键词与城市配置。

### 可控的任务运行

- 「单次测试」支持「只评估不发送」与「真实发送 1 个」两种模式，便于调整规则后验证效果。
- 按钮状态以后端为准，刷新或切换页面后仍显示真实运行状态；停止投递后旧任务在任何检查点都不会再发送消息。
- 城市选择“不限”时自动按全国搜索，不再受账号或 IP 所在城市影响。

## 快速开始

### 1. 准备环境

- JDK 21
- Google Chrome
- Node.js 22（只在需要重新构建管理页面时使用）

### 2. 准备数据库

程序不会自动建表，首次运行需要空数据库：下载 `getjobs.db.template`，重命名为 `getjobs.db`，放到项目根目录的 `db/` 下。已有数据库升级时不要覆盖，否则配置和登录态会丢失。

### 3. 启动

```bash
./gradlew bootRun
```

启动后访问 `http://<服务器地址>:9527/` 打开管理页面，依次完成：

1. 「AI 配置」：填写兼容 OpenAI 接口格式的 `BASE_URL`、`API_KEY`、`MODEL`，以及技能介绍。
2. 「Boss 直聘」：设置关键词、城市、固定招呼语，上传图片简历，编辑岗位匹配规则。
3. 在自动化浏览器中扫码登录，先用「单次测试 → 只评估不发送」确认判定结果，再开始正式投递。

### 4. 重新构建管理页面

修改 `front/` 下的页面后执行：

```bash
./gradlew buildFrontend -PrebuildFrontend
```

管理页面需要从其他机器访问时，构建前设置环境变量 `NEXT_PUBLIC_API_BASE=http://<服务器地址>:9527`。

## 无界面服务器部署

在没有桌面的 Linux 服务器上运行时，用 Xvfb 提供虚拟显示，x11vnc + noVNC 提供网页远程查看，用于扫码登录和处理平台安全验证：

| 组件 | 作用 |
|---|---|
| Xvfb | 虚拟显示，自动化浏览器在其中运行 |
| x11vnc | 把虚拟显示暴露为 VNC，只监听本机 |
| noVNC（websockify） | 在浏览器中查看与操作自动化浏览器 |
| 应用 | `./gradlew bootRun`，以独立的普通用户运行 |

建议四个进程放在同一个 tmux 会话中分窗口运行，服务器重启后按顺序拉起。
